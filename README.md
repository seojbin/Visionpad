# 닷듀밸리 v12

첨부한 v8 게임을 수정한 실행용 패키지입니다. 게임 전체를 새 서버 없이 기존 FastAPI 구조에서 실행합니다.

## 실행

Python 3.10 이상을 권장합니다. 압축을 풀고 이 폴더에서 실행하세요.

```bash
python -m pip install -r requirements.txt
python -m uvicorn game_app:app --host 127.0.0.1 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. HTML을 더블 클릭하면 게임 API가 연결되지 않습니다. 기존 프로젝트에 적용했다면 서버 재시작 후 Ctrl+F5로 새로고침하세요. `web/hardware.mjs`도 함께 배치해야 합니다.

## 이번 변경

- 모든 이동·복귀·상점 화살표를 대칭인 작은 빈 삼각형으로 변경했습니다. 2:1 대각선 반올림 대신 정수 격자의 45도 선을 사용합니다. 클릭 영역은 넓게 유지합니다.
- TTS는 글자 수로 잘라 버리지 않고 상황별로 다시 작성했습니다. 이름·핵심 상태·행동을 앞세우고 가격·수량·성장일·버프 증가율과 남은 틱을 유지합니다. 남은 활동 틱은 하단 디스플레이로만 표시합니다. 버프 지속 시간과 행동 비용 안내는 유지합니다.
- 결과 음성 재생 중 hover 음성이 끼어들지 않습니다. hover는 180ms 머문 뒤 안내합니다. 자막·다시 듣기·음성 끄기·0.8~1.5배 속도 조절을 제공합니다.
- 이동은 항상 0틱이며 음식 버프도 감소하지 않습니다.
- 심기·물·비료는 2틱, 수확·연구·요리 완성은 3틱입니다. 구매·판매·음식 사용과 화면 열기는 기존처럼 0틱입니다.
- 하루는 20틱입니다. 마지막 업무가 완료되면 결과를 안내하고 자동 귀가합니다. 미니게임 실패나 취소에는 시간을 쓰지 않습니다.
- 물을 주고 잠을 자야 성장합니다. 비료는 필수가 아닌 선택 사항이며 사용 즉시 성장 게이지를 1일 진행해 수확까지 남은 날을 줄입니다. 남은 날이 0이면 즉시 수확 가능하며, 다음 수면에는 일반 성장 1일만 적용해 비료 효과를 중복 계산하지 않습니다. 상세 관리의 비료 처리도 물을 준 뒤 사용하도록 통일했습니다.
- 성장 안내의 전체 일수/진행 일수 순서를 바로잡았습니다. 씨앗을 심은 뒤에는 상세 관리 화면에 머무릅니다.
- 드래그 종료 시 마지막 좌표 구간도 반영합니다. 일시정지 중 놓기는 수확·물주기를 완료하지 않습니다.
- 상점 구매/판매 목록의 돌아가기는 바로 마을로 이동합니다.
- 상점·인벤토리의 박스 크기와 간격을 정렬했습니다. 당근·토마토·감자 아이콘을 서로 구분했습니다.

## 패드 화면

추가 제공된 `Dot Canvas · 닷패드 미리보기.html`의 기기 구조와 원본 `workspace.css`를 확인해 다음 순서와 외형을 반영했습니다.

1. 무광 본체와 이중 그래픽 베젤
2. 왼쪽 삼각형 / F1~F4 키 묶음 / 오른쪽 삼각형
3. 기기 오른쪽 상태등
4. 하단 20셀 베젤

그림 편집용 펜·지우개·점자 입력 UI는 게임에 넣지 않았습니다. 하단은 게임의 활동 시간 패널로 사용합니다. 화면의 도트 배열은 실제 게임 엔진 출력입니다. 본체의 상태등은 시뮬레이션 장식이며 실제 연결 여부는 별도의 연결 상태 문구에서 확인합니다.

- F1 미니맵 / F2 현재 장소 / F3 인벤토리 / F4 일시정지.
- 기기 양옆 삼각형: 이전/다음 오브젝트 탐색.
- 마우스·터치: 선택, 누른 채 이동, 놓기. 요리는 단계가 바뀌면 손을 떼고 다음 시작점에서 다시 누르세요.
- 패드에 키보드 초점: 방향키 1칸, Shift+방향키 3칸, Enter 선택, Space 누르기/놓기.
- 오른쪽 오브젝트 버튼도 실제 패드 좌표 입력과 같은 API를 사용합니다.

## v10 음원과 요리 단계

첨부 MP3 5개의 원본 바이트를 그대로 포함했습니다. `cook cut.mp3`는 경로에 공백이 없도록 `web/audio/cut.mp3`로만 이름을 바꿨습니다.

| 상황 | 파일 | 재생 조건 |
|---|---|---|
| 물 뿌리기 | `water.mp3` | 물 미니게임에서 누르는 동안 |
| 비료 뿌리기 | `soil.mp3` | 비료 미니게임에서 누르는 동안 |
| 재료 자르기 | `cut.mp3` | 자르기 단계의 올바른 시작점에서 누르고 이동할 때 |
| 젓기 | `cook.mp3` | 젓기 단계의 올바른 시작점에서 누르고 이동할 때 |
| 진행도 증가 | `correct.mp3` | 물·비료 목표, 수확 대상, 요리 체크포인트를 새로 통과했을 때 |

모든 기본 요리는 `자르기 → 젓기`의 두 단계입니다. 자르기는 지그재그/왕복 경로, 젓기는 시작과 끝이 다른 곡선 경로를 사용합니다. 첫 단계를 마치면 손을 떼고 다음 사각형 시작점에서 다시 누릅니다. 재료와 3틱은 두 단계를 모두 마쳤을 때 한 번만 소비합니다. 젓기에서 실패하면 젓기 단계만 다시 시도합니다. 제한시간·요리 대성공 등급은 없습니다.

설정의 `gesture_steps`에 각 단계의 `kind: cut | stir`, `path`, `tolerance`를 지정합니다. 기존 `gesture`만 있는 설정도 단일 자르기 단계로 실행됩니다. 도트 렌더링·판정·음성·작업음이 같은 단계 정보를 사용합니다.

작업음은 길이가 6~21초이므로 반복 재생하되 손을 떼거나 화면 전환·일시정지·초기화·연결 오류가 발생하면 멈춥니다. 자르기·젓기는 포인터가 450ms 이상 멈추면 작업음을 낮추고 이동 시 복원합니다. TTS 중에는 작업음과 성공음 볼륨을 낮춥니다. 효과음 켜기/끄기와 볼륨은 음성 안내 설정과 별개입니다.

성공 여부는 클라이언트 좌표 추측이 아니라 서버의 `sound_events`에서 받습니다. 이미 통과한 지점을 다시 지나가거나 가만히 있으면 성공음을 내지 않습니다. 한 입력에서 여러 체크포인트를 통과하면 합계와 함께 한 번 알리고, 90ms 이내에 몰린 재생을 제한합니다. 동시 성공음은 최대 2개로 제한해 소리가 뒤늦게 쌓이지 않습니다. 마지막 놓기 구간의 성공도 누락하지 않습니다.

새 파일 `web/game-audio.js`와 `web/audio/` 폴더를 반드시 함께 배치하세요. 외부 음원 서버에 의존하지 않습니다.

검증: 게임 테스트 13개, 오디오 제어 테스트 7개 통과. Chromium에서 물 → 비료 → 자르기 → 젓기 → 요리 완성까지 실행했으며 5개 MP3 전부 로드/디코딩되고 4개 작업음이 올바르게 선택됨을 확인했습니다. 데스크톱·390px 모바일에서 JavaScript 오류와 가로 넘침이 없습니다. 브라우저 오디오 동작은 검증했지만 사용자 기기 스피커에서의 음질·음량은 현장 조정이 필요합니다.

```bash
node --test test_audio.cjs
```

## USB 패드 연결

참조 저장소: https://github.com/eun022/hand_drawing
확인 커밋: `2fdfa07c7f61cdc5a6603c33fc8b643a2b4036fb`
확인 파일: `Dotpad.js`, `DotpadSDK.js`, `DotPadLine.js`, `HomePage.vue`, `aruco_websocket_server.py`.

`web/hardware.mjs`는 참조 코드의 프로토콜에 맞춰 작성한 독립 어댑터입니다.

- Web Serial, 115200 baud, USB VID 1027 / PID 24592 또는 24597.
- 60×40 그래픽: 2×4핀을 1바이트로 묶어 30셀 × 10라인 전송.
- 40×4 하단: 20셀, 0번 라인, 모드 0x80. 시간은 셀 단위로 전체 핀을 올립니다.
- AA55 헤더, 0x0200 출력 명령, XOR 0xA5 체크섬, 0x0201 ACK 확인.
- 변경된 라인만 전송하고, 출력 중 들어온 새 상태는 최신 상태로 합칩니다.
- 실물 F1~F4는 원본 그림 앱의 초기화 기능 대신 게임의 네 기능으로 연결됩니다.

로컬 Chrome 또는 Edge에서 `USB 패드 연결`을 눌러 장치를 선택합니다. ACK가 확인되면 `패드 출력 확인됨`으로 표시합니다. 원본 앱이 같은 포트를 점유하고 있다면 해제한 뒤 연결하세요.

**실물 패드 검증은 하지 못했습니다.** 비트 변환·패킷 조립·분할 수신·체크섬·ACK 처리는 테스트했지만 기기/펌웨어별 실제 핀 출력과 기능 키는 장치에서 확인해야 합니다. Bluetooth 연결은 이번 어댑터에 포함하지 않았습니다.

## 손 추적 서버 연결

참조 저장소의 `socket` 안내에 따라 서버를 실행한 뒤 게임에서 `ws://127.0.0.1:8765`로 연결합니다. 게임 서버는 8000, 손 추적 서버는 8765로 실행하세요.

서버의 `type: frame`, `hand_detected`, `scaled_tip: [x, y]`를 사용합니다. 좌표 범위는 x=0~59, y=0~39이며 이미 도트 좌표이므로 다시 스케일링하지 않습니다.

**원본 서버에는 pinch/down/up 정보가 없습니다.** `누르기 시작`으로 선택·드래그를 시작하고 `손 떼기`로 끝냅니다. 패드에 초점을 두고 Space로도 조작할 수 있습니다. 실제 pinch 인식이 구현된 것은 아닙니다. 누르기 버튼으로 시작한 동작은 손 좌표 소실 또는 1.5초 수신 중단 시 취소해 잘못된 수확 확정을 방지합니다.

HTTPS로 웹을 호스팅한다면 접근 가능한 WSS 연결을 별도로 구성해야 합니다. 실제 카메라와 손 추적 서버는 이 환경에서 검증하지 못했습니다.

## 설정 파일 안내

**원본 첨부에 `game_config.json`이 없어 코드와 제공된 대화를 기준으로 재구성했습니다. 기존 사용자 정의 좌표·수치를 그대로 복원한 파일은 아닙니다.** 기존 설정이 있다면 백업 후 비교해 적용하세요.

요리 테스트용 초기 작물은 토마토·당근·감자 각각 3개입니다. 서버 재시작 또는 새 게임으로 적용됩니다.

기본값은 60골드, 비료 2개, 밭 2개, 토마토 씨앗 3개·당근 3개·감자 2개입니다. 작물 판매가는 각각 12·10·15골드, 씨앗은 10·8·12골드, 비료는 12골드입니다. 요리 가격은 재료 판매가 합의 1.2배를 올림합니다.

이동은 구버전 설정에 비용이 있어도 0틱입니다. 다른 업무는 이번 값을 최소 비용으로 사용하며 설정에서 더 높일 수 있습니다.

## v11 수정 및 검증

- 활동 후/인벤토리 요약의 남은 활동 틱 TTS 제거. 하단 시간 표시와 밤 귀가는 유지.

- 초기 요리 재료 세 종류 각각 3개. 모든 기본 레시피를 바로 시험할 수 있음.
- 물·비료 클릭 시 MP3 해독 전에 손을 떼면 재생이 취소되던 문제 수정. 짧게 눌러도 최대 0.65초 클릭음, 누르고 있으면 연속 작업음. 음소거·일시정지·화면 이동은 대기 중인 클릭음도 취소.
- 프런트엔드 스크립트 버전 갱신. 파일 교체 후 서버를 재시작하고 브라우저를 새로고침하세요.
- v11 검증: Python 회귀 테스트 16개, 오디오 제어 테스트 10개. 두 MP3의 첫 0.65초 디코딩 및 비무음 신호 확인. 이번 수정은 실제 스피커 청취나 실물 닷패드 테스트를 포함하지 않음. 위 Chromium/스크린샷 결과는 v10의 기존 화면 검증 기록.

## v12 오디오 레이어 수정

- 레이어 1: water·soil 클릭음과 water·soil·cut·cook 연속 작업음.
- 레이어 2: correct 성공음. 연속 성공음의 중복 제한도 이 레이어에서만 처리.
- 성공 이벤트에서 작업음 정지/재시작/볼륨 갱신을 제거. 상태가 없는 성공 응답은 작업음에 영향 없음.
