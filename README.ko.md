# Dotdew Valley

[English](README.md) | 한국어

60×40 촉각 디스플레이인 Dot Pad용 농사·생활 시뮬레이션 게임이다. 시각장애인과 저시력 사용자가 촉각과 소리로 게임 세계를 읽고, 읽고 있는 바로 그 화면에서 직접 행동한다. 집, 농장, 마을, 광산, 낚시 호수를 오가며 농사, 요리, 채굴, 낚시, 거래, 연구를 한다. 도형과 영어 음성이 안내하며 점자를 몰라도 된다.

브라우저 시뮬레이터는 마우스와 키보드를 지원한다. USB 또는 블루투스 Dot Pad와 외부 손 추적 카메라를 연결할 수 있고, 별도의 Visual Companion 창이 같은 게임을 이미지로 보여주며 함께하는 일반인이 볼 수 있고 게임을 즐길 수 있다.

## 기획

Stardew Valley의 농사·생활 활동을 촉각으로 탐색하고 수행할 수 있도록 구성한 게임이다. 오브젝트를 찾고, 음성으로 확인하고, 같은 공간에서 직접 활동한다. 시각화 창 없이도 촉각 게임을 플레이할 수 있다.

| 구분 | 용도 |
|---|---|
| 촉각 | 위치, 형태, 이동 경로, 성장과 활동 진행 상태 |
| 음성·효과음 | 이름, 수량, 행동 결과와 방향 안내 |
| Visual Companion | 저시력 사용자와 동행자를 위한 이미지, 큰 수량 표시와 선택 강조 |
| 버튼 | 이동, 메뉴, 선택, 저장·로드 |
| 포인터·손 추적 | 탐색, 목표 쓸기, 경로 따라가기, 오브젝트 선택 |

농사·요리·채굴·낚시·거래·연구·Rowan의 튜토리얼 퀘스트·화초 기르기가 구현되어 있다. 목축과 개·고양이 돌봄, 상점 룰렛도 구현되어 있다. 음악·제작·추가 NPC는 확장 예정이며 관련 이미지를 준비하였다.

## 설치

Python 3.11 이상을 설치한 뒤(3.12 64비트 권장. Windows 설치 파일은 3.12가 있으면 그것을 쓴다) **install-windows.bat**(Windows) 또는 **install-mac.command**(macOS)를 한 번 연다. 프로젝트 안에 `.venv/`를 만들고 `engine/requirements.txt`를 설치하며 영어 음성 두 개를 `.audio/voices/`에 내려받는다. 내려받은 파일은 크기와 SHA-256으로 확인하며, 끊기거나 손상된 파일은 다시 받는다(오류가 나면 설치 파일을 다시 실행한다). 전역 Python에는 아무것도 설치하지 않는다. 이 단계에는 인터넷이 필요하며 계정이나 API 키는 쓰지 않는다. 블루투스 Dot Pad를 쓰려면 설치 파일을 `--with-pad`와 함께 실행해(예: `install-windows.bat --with-pad`) Dot Inc.의 SDK도 내려받는다. 게임, USB 패드, 손 추적은 SDK 없이도 동작한다.

```
python -m venv .venv
.venv\Scripts\activate                 # macOS / Linux: source .venv/bin/activate
python -m pip install -r engine/requirements.txt
python engine/tools/prepare_speech.py --download
```

`python engine/launcher/check_setup.py --synthesize`는 게임을 시작하지 않고 패키지·파일·소리·음성을 점검한다. 설정 파일은 편집기가 BOM을 붙여 저장해도 UTF-8로 읽으며, Windows 실행 파일은 Python을 UTF-8 모드로 실행하므로 한국어(cp949) 코드 페이지와 상관없이 동작한다.

## 실행

**start-windows.bat**(http://127.0.0.1:8003) 또는 **start-mac.command**(http://127.0.0.1:8000)를 열거나 `python engine/launcher/launch_game.py --prepare-demo`(포트 8000)를 실행한다. 실행기는 설치 상태를 확인하고, 게임 서버를 새로 시작하거나 이미 켜진 서버를 재사용하며, 시연 음성을 준비하고 브라우저를 연다. 플레이하는 동안 실행 창을 열어 둔다.

1. 게임 페이지를 클릭하거나 키를 눌러 오디오를 켠다.
2. **Open visual display**를 눌러 시각화 창을 연다(팝업 허용).
3. F3를 길게 눌러 저장한다. 서버를 끄면 진행이 사라진다. 저장 파일은 `saves/`에 있다.

## 조작

| 입력 | 동작 |
|---|---|
| 올려놓기(호버) | 오브젝트 이름과 상태 듣기 |
| 클릭, Enter, F4 | 선택, 시설 사용, 돌 치기, 낚시 |
| 목표나 경로 위로 이동 | 물 주기, 비료, 수확, 요리 경로 따라가기 |
| F1 / F2 | 지도 / 인벤토리. 다시 누르면 돌아온다 |
| F3 짧게 / 길게 | 저장 목록 열기 / 새 슬롯에 저장 |
| 왼쪽·오른쪽 방향키 또는 패드 버튼 | 이동, 뒤로 가기, 페이지 넘기기 |
| W A S D | 캔버스에 포커스가 있을 때 포인터를 한 도트씩 이동 |
| Space | F4와 동일하게 포인터 위치를 한 번 선택. 입력창·버튼에 포커스가 있으면 해당 컨트롤 동작 유지 |
| Shift 누르기 상태 | tts 상세 설명 모드. 떼면 일반 이동으로 복귀 |

장소 순서는 농장 ↔ 집 ↔ 마을 ↔ 광산&호수(상하 이동)다. 장소 이동에는 시간이 들지 않는다. 일반 오브젝트에 포인터를 올리면 정보를 듣지만, 이동 기반 미니게임 안에서는 목표 위로 이동하는 것만으로 진행된다. 진행하지 않고 읽으려면 Shift를 누른다. 현재 F4는 클릭 대체 버튼이며, 제스처 대체가 가능한 경우를 대비해 기존 일시정지 경로는 코드에 남아 있다.

## 기능과 플레이 방법

### 네비게이션과 하단 표시

좌우 방향키로 **농장 ↔ 집 ↔ 마을** 순서로 이동한다. 도착하면 장소 이름을 읽고, 이동할 수 없는 방향에는 짧은 안내를 한다. F1 미니맵에서는 장소를 탐색한 뒤 선택해 이동한다. 현재 위치의 노드는 가운데의 작은 채운 사각형으로 구분하고, 경로는 노드 앞 한 칸에서 끊긴다. 맵 왼쪽 위의 **Guide** 버튼으로 튜토리얼과 기호 범례를 연다([학습 지원](#학습-지원-가이드) 참고). 마을의 경우 상하이동 버튼이 따로 있어 해당 디스플레이 버튼으로 **광산** 과 **호수**로 이동한다. 농장 아래쪽 양 끝(왼쪽: 목장, 오른쪽: 집)과 목장 동쪽 울타리에 촉각 출구 화살표가 있어 방향키뿐 아니라 그래픽에서도 이동할 수 있다. 집의 돌봄(Care) 화면에서도 좌우 방향키가 집 화면처럼 이동한다.

버튼을 눌러 켜는 메뉴창은 현재 지역 위에 띄워지는 창으로, F1·F2 메뉴창에서 같은 키를 다시 누르면 현재 지역으로 돌아간다. 메뉴는 다른 메뉴를 거쳐도 창이 중첩되지 않는다. 여러 페이지가 없는 메뉴 화면에서는 양쪽 방향키로 뒤로가기 역할이 가능하다. F1을 누르면 나오는 미니맵, F3을 누르면 나오는 세이브파일 목록은 방향키로도 직전 화면으로 돌아간다. 

여러 페이지가 존재하는 경우- F2를 누르면 나오는 인벤토리의 방향키는 페이지 이동 전용이며 끝에서는 첫·마지막 페이지라고 안내한다. 따라서 인벤토리는 방향키 사용이 페이지 이동이며 페이지 스크롤을 벗어나는 방향키 또는 동일 버튼 F2로만 닫는다. 

상점은 3단계의 뎁스(마을 - 상점 선택 페이지 - 구매/판매 페이지)로 구성되어 있다. 구매/판매에서는 목록이 2페이지 이상으로 이동 가능한 페이지가 있으면 페이지 전환을 우선하며, 구매·판매 페이지에서 페이지 스크롤을 벗어나는 방향키는 인벤토리와 동일하게 뒤로가기로 동작해 상점 선택 화면으로, 상점 선택 화면의 방향키는 마을로 연결된다.

마을, 집과 같이 아이콘이 적은 화면에는 하단에 디테일한 디스플레이를 생성한다. 디스플레이에서는 버튼과 동일하게 물체를 선택 가능하며, 화살표 표시로 이동도 가능하다. 디스플레이에서 선택 가능한 물체는 볼록한 외곽선과 비어 있는 내부로 그리고, 도로·벽·다른 물체와 최소 한 칸의 내려간 핀으로 떨어뜨린다. 가장자리의 작은 채운 삼각형은 출구다. [촉각 디자인 규칙](#촉각-디자인-규칙)을 참고한다. 

하단 20셀 패널은 평소 활동 시간을 표시한다. 여러 페이지가 있는 목록에서는 전체 폭을 페이지 수로 나눠 페이지 위치 막대로 바뀐다. 상점 단일 페이지에서는 뎁스 구분을 위해 **shop**, **buy**, **sell**을 점자로 표시한다. 페이지 표시는 장소 글자보다 우선하며(sell 페이지가 여러개가 되면 점자는 생략된다) 수면 중에는 패널을 끈다.

데모에서는 shift, 실제 실행에서는 point 제스처를 취하는 것으로 각각의 장소와 호버링 물체에 대한 상세 tts를 출력 가능하다.

### 인벤토리와 아이템 구분

F2를 눌러 소지품을 확인한다. 첫 페이지에는 골드와 사용 가능한 아이템을 두고, 음식이 많으면 음식 페이지를 먼저 정렬해 추가한다. 이후 씨앗·작물·물고기·광물·도구를 표시한다. 수량이 0인 항목은 숨기며 페이지당 최대 12개를 3행 4열로 배치한다. 음식은 선택해서 먹을 수 있다. 반려동물 교환권·돌봄 용품·금 도구 키트도 인벤토리에서 사용하며, 나머지 항목은 정보를 확인한다.

모든 항목은 한 줄 사각형 프레임을 쓴다. 음식과 교환권·돌봄 용품·금 도구 키트 같은 사용 가능한 아이템은 내부 기호 없이 사각형 테두리를 두 겹으로 표시한다. 그 밖의 항목은 공통 기호 14개(씨앗, 작물, 물고기, 광물, 도구, 골드 등, [기호 목록](#기호-목록) 참고) 중 하나를 프레임 안에 표시하며, 기호와 프레임 사이에는 항상 내려간 핀 한 칸이 있다. 종류가 없는 항목은 프레임만 표시한다. 공통 격자를 사용해 위치를 일정하게 유지한다. 시각화 창은 모든 촉각 프레임을 그대로 복제하지 않고 이미지 카드와 수량을 표시한다.

### 집, 시간과 수면

집에서는 침대를 선택해 잠들고, 연구대에서 업그레이드하며, 주방에서 요리한다. 네 번째 **Care**에서 Plants와 Pets를 고른다. 하단 화분은 화초 관리 화면을, 동물집은 펫 슬롯을 연다. 새 게임은 골드 60개, 비료 2개, 작물 씨앗과 요리용 채소 각 3개로 시작한다.

시간은 활동에 소모되는 틱이다. 현재 하루 한도는 20틱이다. 심기·물·비료·돌 파괴·낚시는 각각 2틱, 수확·연구·요리는 3틱, 이동은 0틱이다. 채광은 한 번 칠 때가 아니라 돌을 완전히 부술 때 차감한다. 음식 효과에 따라 시간 비용이 달라질 수 있다.

활동 시간이 소진되면 집으로 돌아오고 침대를 선택해야 다음 날이 된다. 수면 중 촉각 패널이 2초간 꺼지고 배경음악도 멈춘다. 다음날이 되면 물을 준 작물이 자라고 화초 상태가 갱신되며 광산의 돌도 새로 생긴다. 시각화 창은 시간대와 수면 전환을 함께 표현한다.

### 농사: 심기, 물주기, 비료와 수확

1. 농장에서 밭을 선택한다. 농장 화면에서는 밭 내부가 아래부터 채워지며 성장도를 나타낸다.
2. 빈 밭에서는 심기를 고른 뒤 보유 씨앗을 선택한다. 작물이 있으면 성장·물·비료 상태를 확인한다.
3. 물주기나 비료주기를 선택하고 목표 도트 위로 손이나 포인터를 이동한다. 클릭은 필요 없이 단순 드래그로 동작한다.
4. 물을 준 뒤 잠들면 작물이 자란다. 비료는 사용 즉시 성장일을 하루 앞당기는 선택적인 성장 보조 수단이다.
5. 다 자란 밭에서 수확을 선택하고 모든 목표를 통과한다. 제한시간과 미니게임 점수에 따른 수확량 배율은 없다. 기본 수확량·음식 효과·화초와 반려동물 보너스로 결과를 계산하며 연구를 통해 얻는 효과인 씨앗 회수는 별도로 판정해 씨앗을 돌려준다.

목표 도트는 3x3의 십자 형태로 구성된다. 물·비료 목표와 요리 경로는 접촉 후 잠시 남았다가 사라진다. 현재 지연은 200ms이며, 촉각으로 읽을 시간을 1초로 늘리려면 1000ms로 설정한다. 지연 표시를 사용하는 활동은 해당 표시가 끝난 뒤 완료 처리한다.

### 요리와 음식 효과

주방에서 요리법을 고르고 재료를 선택한다. 필요한 재료를 모두 선택하면 자동으로 조리가 시작된다. 시작점부터 두 단계 경로를 차례로 따라간다. 진행이 멈추면 재개할 위치를 4x4 점자 사각형으로 표시한다. 재료와 요리 시간은 첫 단계가 아닌 음식 완성 시에 소모하며, 제한시간은 없다. 농장과 동일하게 클릭 없는 드래그로 동작한다.

1차 요리는 재료에 따라 바뀐다 - 생선은 가로 손질경로, 채소는 세로 썰기경로, 2차 요리는 조리법에 따라 바뀐다 - 튀김/구이/수프젓기가 구현되었다.

| 채소 요리 | 재료 — 각 1개 | 효과 | 지속시간 |
|---|---|---|---|
| Tomato carrot stew | 토마토·당근 | 수확량 증가 | 게임 시간 6시간 |
| Potato tomato soup | 감자·토마토 | 곡괭이 보호 | 게임 시간 10시간 |
| Vegetable fritters | 감자·당근 | 시간 소모 감소 | 게임 시간 10시간 |

| 생선 요리 | 채소 | 사용할 수 있는 생선 | 효과 |
|---|---|---|---|
| Grilled fish | 감자 | 고등어·잉어·연어 | 철·다이아몬드·희귀 어종 획득 확률 증가, 12 / 14 / 16시간 |
| Fish stew | 토마토 | 정어리·메기·무지개송어 | 판매가 증가, 3 / 4 / 5회 판매 |
| Fried fish | 당근 | 배스·가자미 | 확률적으로 획득량 2배, 12 / 14시간 |

생선의 경우 재료 희귀도에 따라 음식 이름 앞에 **Simple(소박한)**, **Ordinary(평범한)**, **Luxurious(호화로운)** 를 붙이고 해당 레어도에 따라 효과 강도가 달라진다. 설명에는 지속시간이나 남은 판매 횟수를 표시하되 확률·배율은 직접 안내하지 않는다. F2 인벤토리에서 먹으면 적용되며, 음식 효과는 한 번에 하나만 유지된다. 다른 음식을 먹으면 교체된다. 시간형 효과는 소비한 게임 시간만큼 줄고, 판매형 효과는 판매 성공 시에만 횟수가 줄어든다.

요리를 성공하면 기반 재료의 1.5배정도 가격이 상승해 효율적인 재화획득이 가능하다.

### 채광

광산에서 돌을 선택하면 타격한다. 입장은 자유지만 돌을 치려면 곡괭이가 필요하다. 상점에서 한 개만 보유할 수 있고, 부서지면 다시 구매한다. 하루 최대 7개의 돌이 간격을 두고 생기며 기본적으로 세 번 클릭·Enter·F4를 누르면 부서진다. 손상에 따라 정해진 패턴으로 내부 도트가 줄지만 외곽은 유지해 위치와 크기를 읽을 수 있다.
곡괭이는 9회 타격 이후부터 파괴 확률이 5퍼센트씩 점진적으로 증가한다.

돌을 부술 때마다 정해진 확률에 따라 돌·구리·철·다이아몬드를 얻으며 연구와 음식이 결과를 개선할 수 있다. 타격, 바위 파괴, 레어템 획득,도구 파괴에 서로 다른 소리를 사용한다. 도구가 파괴되는 타격에서는 일반 타격·바위 파괴음 대신 도구 파괴음을 재생한다. 내구도와 획득 확률은 공개하지 않는다.

### 낚시

장비 없이 입장할 수 있지만 낚시에는 낚싯대가 필요하다. 기본 가격은 100골드이며 한 개만 보유한다. 스테레오 헤드폰을 사용하고 반복되는 물소리를 따라 포인터를 움직인다. 물소리는 포인터를 기준으로 목표 방향에서 들리며 가까울수록 커진다. 촉각 테두리가 호수 범위를 나타내고, 시각화에는 명중 구역을 공개하지 않는다. 목표 지점에 가까울수록 꽝 확률이 줄어들고 희귀 어종 획득 확률이 상승한다.

호수 안에서 클릭·Enter·F4를 누르면 물고기를 낚는다. 성공과 꽝 모두 2틱을 사용하며 해당 행동 후 목표 지점은 이동한다. 누르고 있어도 연속으로 낚지 않고, 원형 경계의 호수 밖 입력은 무시한다. 획득 시 splash, 희귀 어종이면 shine도 함께 재생한다. 호수는 기본 음악을 낮춰 유지하고, 음성 안내 중에도 탐색 물소리는 줄이지 않는다. 낚싯대 사용량은 성공 시에만 증가하며, 사용량이 증가할수록 5회 이후 파괴 확률이 10퍼센트씩 점진적으로 늘어난다.

| 물고기 | 기본 판매가 | 요리 용도 |
|---|---:|---|
| 정어리 / 고등어 / 배스 | 각 24골드 | 스튜 / 구이 / 튀김 |
| 잉어 / 메기 / 가자미 | 각 27골드 | 구이 / 스튜 / 튀김 |
| 연어 / 무지개송어 | 각 36골드 | 구이 / 스튜 |

### 상점과 요일 효과

마을의 상점을 선택한 뒤 Sell·General goods·Tools·Calendar를 고른다. 아이템에 포인터를 올려 가격과 보유량을 확인하고 선택하면 하나씩 거래한다. 작물 씨앗·사료·반려동물 약·도구·가축·일부 광물을 구매하고, 거래 가능한 작물·음식·물고기·광물·생산물을 판매한다. 비료와 꽃씨는 직접 판매하지 않고 룰렛 보상으로 제공한다. 목록은 스크롤 대신 페이지로 나눈다. Calendar는 다른 화면을 열지 않고 오늘의 효과만 읽는다.

| 요일 | 효과 |
|---|---|
| 월요일 | 광석 구매가 20% 할인 |
| 화요일 | 요리 판매가 20% 증가 |
| 수요일 | 물고기 판매가 20% 증가 |
| 목요일 | 작물 씨앗 구매가 20% 할인 |
| 금요일 | 광석 판매가 20% 증가 |
| 토요일 | 곡괭이·낚싯대 구매가 20% 할인 |
| 일요일 | 거래 가능한 모든 품목 판매가 20% 증가 |

1일차는 월요일이다. 적용되는 배율마다 소수점을 버리며, 판매가 증가 음식 효과도 화면 가격과 지급액에 반영한다.

### 룰렛과 특별 아이템

General goods의 첫 항목인 **Prize draw**를 200골드에 구매한다. 전용 바퀴 아이콘으로 구분하며, 상점 하단의 상인 옆 바퀴를 선택해 바로 구매할 수도 있다. 결과는 즉시 지급하고 룰렛 효과음이 시작된 뒤 최소 1초가 지나면 음성으로 안내한다. 음성 준비가 더 오래 걸리면 준비된 뒤 재생한다.

| 보상 | 확률 | 수량 |
|---|---:|---|
| 식물 영양제 | 12% | 1개 |
| 특수 사료 | 12% | 1개 |
| 금 도구 키트 | 10% | 곡괭이·낚싯대 중 1개 |
| 반려동물 교환권 | 6% | 개·고양이 중 1개 |
| 꽃씨 | 6% | 나팔꽃·해바라기·난초 중 1개 |
| 다이아몬드 | 1% | 1개 |
| 비료 | 20% | 3개 |
| 작물 씨앗 | 33% | 한 종류 3개 |

같은 보상 분류 안의 종류는 동일한 확률로 고른다. 룰렛 가격은 요일·음식 할인과 무관하게 200골드이며 할인 횟수를 소비하지 않는다. 교환권은 입양에 사용하거나 정확히 300골드에 판매한다. 이 판매에도 요일·음식 효과를 적용하거나 판매 효과 횟수를 차감하지 않는다.

식물 영양제는 살아 있는 화초의 건조·개화 노화 누적을 초기화하고 6일 동안 시듦을 막는다. 시든 식물은 되살리지 않는다. 특수 사료는 반려동물의 친밀도를 크게 높인다. 금 도구 키트는 해당 도구를 보유한 상태에서 사용하며 마모를 초기화하고 이후 유효 사용량을 4분의 1로 계산한다. 강화는 중첩되지 않고 도구가 부서지면 사라진다. 확률식이 유지되므로 정확히 네 배 사용을 보장하지는 않는다.

다음 보상 5개를 미리 정하고, 구매할 때마다 첫 보상을 지급한 뒤 하나를 보충한다. 이 목록과 난수 상태는 일반 저장 슬롯에 함께 저장한다. 로드하면 해당 슬롯의 보상 순서도 복원한다. 구매에 실패하면 목록은 바뀌지 않으며, 별도 확률 파일은 만들지 않는다.

### Rowan과 튜토리얼 퀘스트

Rowan은 상점 옆에 있다. 선택하면 마을 화면을 유지한 채 대사를 듣는다. 퀘스트 아이템을 제출할 때만 별도 선택 페이지를 열며, 시각화는 초상화와 대사를 겹쳐 표시한다. 호버 음성이 진행 중인 퀘스트 대사를 덮어쓰지 않고, 새 대화는 이전 대화를 교체한다.

첫 대화에서는 스튜와 같은 수확 효과를 가진 **Rowan's soup**를 받는다. F2에서 먹거나 상점에 판매한 뒤 돌아오면 작물 씨앗을 종류별로 하나씩 받는다. 수프의 기본 판매가는 100골드다. 다음 대화에서는 농사 안내와 채소 요청을 받는다. 제출 화면에서 보유 작물 하나를 선택하면 100골드를 받으며 양쪽 방향키로 취소할 수 있다. 선물·보상·진행 상태는 저장된다. 이후 조언과 최근 활동에 대한 반응도 Rowan의 음성으로 들려준다.

사용자 골드가 0이거나 심을 수 있는 작물이 없어 돈을 더 이상 획득하지 못하는 락을 해결하기 위해, 보유 씨앗이 존재하지 않을 경우 Rowan이 공짜로 당근 씨앗을 지급하도록 설정하였다.

### 목장

목장은 농장 왼쪽에 있다. 처음에는 동물이 없으며, 상점의 **Tools**에서 닭을 100골드, 양을 250골드에 구매한다. 종류별로 한 마리씩 기를 수 있다. 상단 아이콘을 선택하면 동물 상세 화면을 열고, 하단 장면에서는 보유 동물이 움직이거나 방향을 바꾸는 모습을 확인한다. 상세 그림도 숨을 쉬듯 조금씩 움직인다.

상세 화면에는 **Feed**와 **Collect eggs** 또는 **Shear wool** 버튼이 있다. 동물은 사료 없이도 풀과 씨앗을 먹지만, 사료를 주면 생산 주기를 앞당기고 탈출을 방지하는 데 도움이 된다. 잡화에서 공용 **Animal feed**를 구매하며 현재 기본 가격은 80골드다. 동물마다 하루 한 번 줄 수 있다. 생산물이 이미 준비되었거나 다음 날 준비될 상태라면 즉시 생산하지 않고 다음 주기에 단축 효과를 적용한다.

쓰다듬기는 숨겨진 상호작용이다. 동물 몸 위에서 포인터를 좌우로 움직이면 브러시 소리가 나며, 움직임이 합계 3초에 도달하면 하루 한 번 친밀도가 오르고 해당 동물의 메인 울음소리가 나온다. 별도의 쓰다듬기 버튼이나 퍼센트 표시는 없다. 상태는 **Indifferent**, **Recognizes you**, **Seems happy** 순서로 달라진다. 쓰다듬지 않았다는 이유만으로 친밀도가 감소하지는 않지만, 오랫동안 사료를 주지 않거나 생산물을 방치하면 감소한다. 사료를 오래 주지 않으면 탈출할 수 있으며 친밀도가 높을수록 더 오래 머문다. 탈출한 동물은 목장 입장 시 짧게 안내한다. 친밀도 수치와 탈출 확률은 플레이 중 공개하지 않는다.

| 동물 | 생산물과 대기 기간 | 회수 방법 |
|---|---|---|
| 닭 | 1~2일 후 새 달걀이 생긴다. 보통 1개, 가끔 2개가 나오며 최대 3개까지 쌓인다. | 닭 아래 달걀을 직접 선택하거나 Collect eggs 버튼으로 회수 화면을 열어 선택한다. |
| 양 | 2~4일 후 양털이 준비된다. 회수 전까지 유지되며 주기가 지나도 추가로 쌓이지 않는다. | 준비된 양이나 Shear wool 버튼을 선택해 털깎기 화면을 연다. 클릭을 유지하지 않고 쓸면 원형 지우개처럼 개별 도트가 사라지며 일정 면적을 깎으면 완료된다. |

준비 상태는 수량 없이 **Eggs ready**, **Wool ready**로 안내하고, 실제 회수 시 획득 수량을 말한다. 양털은 기본 2~5개를 얻으며 가축 보금자리 연구로 달걀이나 양털을 추가 획득할 수 있다. 달걀 회수와 털깎기 완료는 각각 3틱을 사용한다. 기본 판매가는 달걀 70골드, 양털 100골드다.

목장에서는 보유한 동물의 주기적 울음소리만 들리고, 상세 화면에서는 선택한 동물의 소리만 들린다. 입장과 상호작용 완료에는 메인 울음소리를 사용하며 쓰다듬기 소리와 동시에 재생될 수 있다. 사료주기에는 전용 효과음, 털깎기에는 전용 자르기 소리가 나온다. 닭이 있으면 수면 후 아침 울음소리도 재생한다. 소유 여부, 생산 상태, 친밀도, 사료 기록과 진행 중인 털깎기는 저장된다.

달걀과 당근으로 **Fried egg**를 만들 수 있다. 바운싱 형태의 달걀 깨기 경로와 튀김 경로를 차례로 완료한다. 먹으면 다음에 성공하는 연구 구매 한 번의 골드 비용을 20% 할인하며, 재료 수량은 줄어들지 않는다.

### 연구

집의 연구대에서 업그레이드를 확인하고 선택하면 골드와 재료를 소비한다. 목록은 한 행에 세 개씩 배치한다. 연구는 활동 시간을 사용하고 진행 상태도 저장하며 추후 다양하게 추가할 예정이다.

| 연구 | 재료 | 효과 |
|---|---|---|
| Seed recovery | 골드·구리 | 씨앗 회수 개선, 최대 2단계 |
| Farm expansion | 골드·돌 | 기본 2개에서 최대 6개로 밭 확장 |
| Mineral luck | 골드·철 | 광물 획득과 보너스 수량 개선, 최대 2단계 |
| Animal shelter | 1단계: 150골드·양털 2개, 2단계: 250골드·양털 4개 | 회수 시 달걀·양털 추가 획득, 최대 2단계 |

플레이 안내에는 정확한 확률 대신 연구 단계를 안내한다.

가축 보금자리는 달걀이나 양털을 회수할 때 기본 획득물 한 개마다 독립적으로 추가 획득을 판정한다. 1단계는 15%, 2단계는 30%다. 예를 들어 2단계에서 달걀 2개를 회수하면 30% 추첨을 두 번 하며, 성공한 횟수만큼 달걀을 더 받는다. 보너스로 받은 물품은 다시 추첨하지 않는다. 닭과 양 모두 생산물 한 개당 같은 확률을 적용한다. 회수 전 둥지 저장 한도는 여전히 3개이며, 연구 보너스는 회수할 때 더한다.

연구의 간단 음성은 이름과 다음 단계의 골드·재료 비용을 읽는다. 상세 음성은 다음 단계, 필요 재료와 효과를 안내하며 가축 보금자리 효과는 “Increased yield”로 표시한다. 최대 단계에서는 최대 단계임을 안내하고 구매할 수 없다. 연구 단계는 저장되며 해당 항목이 없는 이전 저장은 0단계로 시작한다.

### 화초 기르기

룰렛에서 얻은 나팔꽃·해바라기·난초 씨앗을 집의 **Care → Plants** 또는 하단 **Flower pot**에서 골라 심는다. 화분은 한 개를 사용한다. 기본적으로는 골드 소모량이 많고 실제 이득이 적은 꾸미기 기능이며, 집의 작은 그림과 확대 화면에서 새싹·줄기·꽃·시듦 상태를 관찰할 수 있다. 상세 화면은 식물 위에 물주기와 화분 비우기 버튼을 둔다.

꽃이 핀 동안 특수 효과를 얻는다. 해당 부분은 숨겨진 효과이며, 나팔꽃의 경우 작물 수확량이 1씩 증가한다.

물주기를 고른 뒤 실제 화분 부분에 포인터를 합계 3초간 둔다. 클릭 없이 접촉 시간으로 완료를 판정한다. 매일 물을 주고 잠들면 새싹에서 줄기까지 이틀, 줄기에서 꽃까지 이틀이 걸린다. 꽃이 피면 줄기로 돌아가지 않고 꽃 상태를 유지하지만 시간이 지날수록 시들 가능성이 높아진다. 물을 주지 않은 날도 위험을 높인다. 시든 식물에는 물을 줄 수 없으며 화분을 비운 뒤 다시 심는다. 개화 보너스와 시듦 확률은 플레이 중 공개하지 않는다. 현재 세 종류는 성장·물주기 규칙과 개화 효과를 공유한다. 꽃 도트와 기존 씨앗 이미지로 종류를 구분하며, 추가 화초의 전용 상세 그림은 아직 적용하지 않았다.

### 반려동물

룰렛에서 얻은 개·고양이 교환권을 인벤토리에서 사용한다. 종별 이름 12개 중 하나를 고르면 **Cat Luna**처럼 종류와 이름을 붙여 입양한다. 이름 확정 전에는 교환권을 소비하지 않는다. 같은 종류를 여러 마리 기를 수 있으며 최대 6마리다.

집의 **Care → Pets** 또는 하단 동물집에서 6칸의 펫 슬롯을 연다. 원하는 동물을 고르면 상세 화면이 열리고 그 동물이 집에 나온다. 집에서는 좌하단 범위 안에서 움직이며 상세 화면에서도 조금씩 이동한다. 위치·방향·포즈는 3~5초 간격으로 바뀌고 쓰다듬기는 포즈를 강제로 바꾸지 않는다. 개와 고양이 도트는 몸·꼬리 연결을 유지하면서 주둥이 돌출부를 줄였다.

| 상세 버튼 | 동작 |
|---|---|
| Give something | 공용 Animal feed·특수 사료를 선택해 준다. 약은 아플 때만 표시하고 사용할 수 있다. |
| Receive | 준비된 선물을 받는다. 동물 옆 선물을 직접 눌러도 회수한다. |
| Change pet | 펫 슬롯을 열어 집에 꺼낼 동물을 바꾼다. |
| Let pet go | 정말 보낼지 확인한다. Confirm은 보내기, Keep pet은 취소다. |

몸 위에서 포인터를 3초간 움직이면 하루 한 번 친밀도가 오른다. 퍼센트나 별도 쓰다듬기 버튼은 없으며 보상 시 메인 울음소리가 난다. 일반 사료는 하루 한 번 줄 수 있고 특수 사료도 기존 feed 효과음을 사용한다. 사료를 주지 않으면 배고픔과 질병이 생기며 잡화에서 기본 30골드에 파는 약으로 치료한다. 반려동물은 가축과 달리 죽거나 탈출하지 않는다.

친밀도 상태는 **Getting to know you → Recognizes you → Trusts you**다. 건강하고 먹이를 먹은 동물은 친밀도에 따라 선물을 준비한다. 개는 작물 씨앗, 고양이는 하급 물고기를 주며 선물은 회수 전까지 하나만 보관한다. 최고 친밀도의 건강하고 먹이를 먹은 동물이 있으면 작물 수확량이 1개 늘어난다. 여러 마리의 보너스는 중첩하지 않으며 음식 효과와는 별개다. 수치와 확률은 플레이 음성에 노출하지 않는다.

집에서는 보유 동물의 주기적 울음소리가 번갈아 나오고 상세 화면에서는 선택한 동물만 운다. 입장·돌봄에는 메인 소리를 사용하며 쓰다듬기와 함께 재생할 수 있다. 개체별 피치는 입양 때 정해 저장한다. 현재 고양이 routine 게인은 0.8, 기본 routine 게인은 0.35다.

### 저장과 로드

F3를 0.8초 길게 누르면 새 파일에 저장한다. 누르고 있는 도중 **Game saved.** 가 나오며, 손을 떼도 현재 화면을 유지한다. 짧게 누르면 저장 목록을 열고 슬롯을 선택해 불러온다.

`saves/`에는 최근 12개의 JSON 저장 파일만 유지하며 오래된 슬롯은 삭제한다. 골드·아이템·날짜·밭·연구·음식 효과·퀘스트·광산·낚시·화초·반려동물 상태와 선택한 펫, 금 도구 강화, 다음 룰렛 보상 5개를 복원한다. 게임이 업데이트되도 로드 가능하도록 예외처리를 하였다. 장치 연결·카메라 보정·브라우저 음향 설정은 진행 저장과 별개다. 서버 메모리의 진행은 자동 영구 저장이 아니므로 종료 전에 저장이 필요하다.

## 촉각 디자인 규칙

촉각 화면은 공개된 촉각 그래픽 지침을 닷패드(60 × 40 단일 높이 핀, 핀 간격 약 2.5 mm)에 맞게 적용한다. 규칙은 `engine/display/tactile.py`에 있다. `python engine/tools/tactile_audit.py [--show] [--png DIR]`는 모든 화면을 그려([도트 검토](#도트-검토) 참고) 위반 사항을 보여 주고, `engine/tests/python/display/test_tactile_rules.py`는 규칙을 어긴 화면이 있으면 실패한다. 대괄호 숫자는 [참고 문헌](#촉각-디자인-참고-문헌) 번호다.

### 아이콘별 출처와 인식 근거

이 그림들은 아직 시각장애 독자에게 시험하지 않았다. *근거* 열은 설계 이유와 그 바탕이 된 연구이며 시험 결과가 아니다. "팀"은 `main`에 있던 프로젝트 기존 아이콘(채운 실루엣)에서 왔다는 뜻이고, "이번 개선"은 촉각 업데이트에서 다시 그렸다는 뜻이다. 출판된 검증 기호 세트에서 가져온 아이콘은 없다. 찾은 연구들은 이 기호 자체가 아니라 단순 도형과 그림을 시험했다.

### 도트 검토

등록된 모든 화면(46개)과 미니게임, 수확, 요리, 달걀 줍기, 털 깎기, 화초, 아이템을 채운 인벤토리 상태까지 모두 61개 화면을 `python engine/tools/tactile_audit.py --png DIR`로 그려 두 번 확인한다.

1. **규칙 검사.** `audit()`는 채움과 오브젝트 범위를 검사한다. `SymbolTrace`는 각 핀을 어느 그리기 호출이 올렸는지 기록하므로, 한 오브젝트 범위 안에 둘 다 들어 있어도 기호가 벽, 프레임, 도로, 다른 기호에 닿으면 잡아낸다(General goods 가방이 자기 계산대에 닿은 것을 기존 범위 검사는 놓쳤다).
2. **눈으로 확인.** 오브젝트 범위를 표시한 그림과 표시하지 않은 그림을 모두 보며 규칙으로 판단할 수 없는 점(어색한 모양, 붐비는 영역, 불분명한 형태)을 확인했다.

3차 검토에서 찾아 고친 것: 계산대에 닿은 General goods 가방, 프레임에 닿은 경품 뽑기 바퀴, 구분선에 닿은 성장 게이지, 채운 화분, 경로 위에 겹친 요리 시작 표시. 수정 후 감사 결과는 문제 0개다. 의도적으로 남긴 것: 채운 광산 바위와 털 깎기 화면.

### 학습 지원: 가이드

맵 장면은 아이콘을 한 줄로 나열하는 것보다 체험하기는 좋을 수 있지만 더 많이 익혀야 한다. 촉각 그림은 맥락 없이 이름을 맞히기 어렵다. 여러 연구를 종합하면 돌출선 그림의 이름을 맞힌 비율은 평균 약 42 %(범위 9–85 %)다 [5, Picard & Lebaz 2012 인용]. 범주를 알려 주거나 설명을 먼저 들려주면 정확도가 오른다. [5]에서는 51.6 %에서 70.7 %로 올랐다([8]도 참고). TactIcons 연구에서 "학습 가능한" 아이콘은 범례를 한 번만 보고도 기억되었다 [3]. 게임 접근성 지침은 언제든 다시 볼 수 있는 튜토리얼과 실패 없이 연습할 수 있는 방법을 요구한다 [10, 11]. 그래서 다음을 추가했다.

- **가이드** (`game/guide/`). F1 맵 왼쪽 위의 Guide 버튼으로 연다. 주제는 *Touch and listen*(터치와 듣기), *Select*(선택), *Sweep tasks*(쓸어내기 작업), *Keys*(키), *Screen layout*(화면 구성), *Symbol key*(기호 범례) 여섯 가지다. 주제를 만지면 이름을 말하고, 선택하면 설명을 읽어 준다. 시간, 골드, 아이템을 쓰지 않고 언제든 반복할 수 있다.
- **기호 범례.** 한 페이지에 기호 네 개씩, 다섯 페이지로 나눴다(*기르고 찾는 것*, *도구와 거래*, *장소와 사람*, *신호*, *동물*). 그래서 어느 페이지도 기호 5개 한도를 넘지 않는다. 동물을 선택하면 **동물 갤러리**가 열려 게임과 같은 큰 그림을 보여 주고 무엇을 만져 볼지 설명한다. 오른쪽 방향키로 다음 동물을 본다. 기호를 만지면 이름을, 선택하면 모양과 쓰이는 곳을 말한다. 좌우 방향키로 페이지를 넘긴다.
- 마을의 Rowan 튜토리얼 퀘스트는 그대로 활동 방법을 가르친다. 가이드는 패드를 읽는 방법을 가르친다.

**동물 그림(고양이, 개, 닭, 양)은 알아볼 수 있을까?** 촉각만으로는 어려울 가능성이 크다. 익숙한 물체를 그린 돌출선 그림도 알아보기 어렵고, 선천성 시각장애인은 더 어려워한다 [6]. 범주 정보를 주면 식별이 좋아진다 [8]. 시각장애 참가자들은 그림 이름을 맞히는 것보다 짝 맞추기를 훨씬 정확하게 했다 [8]. 닷패드 자체에서 동물 인식을 다룬 연구는 찾지 못했다. 그래서 이 게임은 그림을 알아보는 데 의존하지 않는다.
- 모든 동물은 호버하면 이름과 상태를 말한다.
- 큰 그림은 팀의 원래 그림 비율을 따른 온몸 옆모습이며, 종을 구분하는 특징을 강조한다(고양이: 뾰족하고 긴 두 귀, 위로 말린 꼬리; 개: 긴 주둥이, 처진 귀, 굵은 다리, 짧은 꼬리). 다리는 채우고, 몸통은 외곽선 안에 쓰다듬을 선 무늬를 넣고, 머리는 빈 외곽선으로 둔다.
- 7 × 5 크기의 작은 아이콘은 한 화면 안에서 서로 구분되기만 하면 된다.
- 가이드의 동물 갤러리에서 게임에 나오기 전에 각 그림을 이름과 함께 만져 볼 수 있다. 범주 단서를 주어도 인식률은 31–52 % 정도이므로 [17, 18] 음성이 주된 정보 통로다.

그림을 바꾸기 전에 촉각 초보자 3명 이상과 선천성 시각장애인 3명 이상에게 시험해 본다 [3].

버그 수정:

- **상점의 Tools 버튼에 General goods 기호가 표시되었다.** `shop_tools_choice`의 `choice`가 `"buy"`였다. 이제 `"tools"`이고 도구 기호를 표시한다. 상점 장면의 도구 계산대도 가방 대신 도구를 보여 준다.
- **Windows에서 쓰다듬기 소리가 빠질 수 있었다.** 피드백 ID를 `time.monotonic_ns()`로 만들었는데, 이 값은 약 15 ms 단위로만 바뀐다. 그래서 두 번째 완료가 첫 번째와 같은 ID를 받으면 브라우저가 소리를 재생하지 않았다. 이제 ID에 카운터를 더한다.
- **오래된 테스트.** 목장과 연구 테스트가 이전 가격(달걀 70, 사료 30, 축사 양털 2와 4)을 기대했다. 설정은 이미 달걀 50, 사료 80, 양털 3과 6으로 바뀌어 있었다. 테스트를 설정에 맞췄고, 게임 규칙은 바꾸지 않았다.

닷패드 자체에서 아이콘이나 도형 인식을 다룬 동료 심사 연구는 찾지 못했고, 간격 수치를 정한 국내 촉각 그래픽 표준도 찾지 못했다. 사용자 평가로 확인할 질문:
- 단일 높이 핀에서 큰 외곽선과 큰 채운 모양 중 무엇이 나은가
- 내려간 핀 한 칸(약 2.5 mm)으로 충분한가, 두 칸이 필요한가
- 손가락이 핀을 누를 때 가는 외곽선이 얼마나 잘 유지되는가

Bluetooth는 `engine/web/core/pad/vendor/`의 SDK 3.0.3과 의존 파일이 필요하다. 설치 옵션 `--with-pad` 또는 `python engine/launcher/prepare_pad.py`로 준비한다. USB에는 해당 SDK가 필요 없다. 대상 컴퓨터의 브라우저 지원과 장치 권한을 확인한다. HTML은 파일로 직접 열지 않고 서버로 접속하며, 웹 수정 후에는 강력 새로고침하고 시각화 창도 다시 연다.

### Visual Companion과 이미지

**Open visual display**로 읽기 전용 창을 열고 원래 게임 탭도 유지한다. 장소·선택·활동 진행·획득물·대사·화초 단계·시간대를 따라간다. 각 밭과 바위는 실제 게임 객체와 연결되며 인벤토리·상점 카드도 촉각 화면과 같은 페이지의 항목을 보여준다.

| `engine/web/spectator/` 아래 | 역할 |
|---|---|
| `standalone.html`, `boot.js` | 별도 창 진입과 시작 연결 |
| `display.js` | 게임 페이지에서 사용하는 기존 실행용 묶음. 별도 창은 `viewer.js`를 읽음 |
| `viewer.js`, `model.mjs`, `viewer.css` | 장면 그리기·상태의 배치 변환·UI 스타일 |
| `visual-assets.json` | 배경·시설·아이템·스프라이트 영역 등록 |
| `scene-objects.json` | 시설 위치·크기·순서 |
| `assets/` | 공통 이미지. 기능별 이미지는 `game/<feature>/assets/`에도 배치 |

별도 창의 집에는 동물집과 움직이는 선택 펫을, 상인 옆에는 룰렛을 표시한다. 반려동물 상세 화면은 현재 도트 대체 화면을 사용한다.

배경·시설·아이템 등록을 분리해 기존 이미지를 재사용한다. 아직 시각화를 만들지 않은 화면은 도트 화면으로, 이미지 없는 아이템은 이름 카드로 대체한다. 신규 이미지를 추가할 때 기존 시트는 유지한다. **현재 저장소 규칙상 `display.js`를 수정하거나 재생성하면 안 된다.** 원본 파일과 합쳐지지 않은 수동 수정이 남아 있기 때문이다(후속 작업 F5). 이전 문서의 `build_display.py`로 다시 생성하라는 안내는 현재 적용하지 않는다.

### 오디오와 음성

`GameAudio`가 배경음악·작업음·성공음·단발음·합성 안내음을 재생한다. 공통 녹음은 `engine/web/audio/`, 기능별 녹음은 `game/<feature>/audio/`에 있다. `GameSpeech`는 서버에서 생성한 음성을 별도 게인으로 재생한다. TTS와 일반 비입체 효과음은 비입체로 유지한다.

| 음원 | 사용 상황 |
|---|---|
| `background-basic`, `background-minigame`, `background-shop` | 그룹별 음악. 같은 그룹에서는 다시 시작하지 않음 |
| `water`, `soil`, `crop`, `cut`, `cook` | 물·비료·수확·조리 작업음. 성공음과 독립 |
| `correct` | 목표 진행과 일반 획득 |
| `step`, `door`, `coin` | 이동·상점 입장·거래/유료 연구 |
| `pickaxe`, `break`, `destroy`, `shine` | 타격·바위 파괴·도구 파괴·희귀 획득 |
| `splash` | 물고기 획득. 희귀 획득 시 shine과 동시 시작 |
| `sleep` | 아침 전환 후에도 이어지는 1회 수면음 |
| `dog_main`, `cat_main`, `dog_routine`, `cat_routine` | 반려동물 입장·돌봄과 주기적 울음소리. 개체별 피치 적용 |
| `feed`, `brush` | 사료·특수 사료와 쓰다듬기. 울음소리와 독립 재생 |
| `roulette` | 룰렛 구매. 소리 시작 후 최소 1초 뒤 결과 음성 |
| 합성 안내음·목표 비콘 | 선택·실패·진행·선택적으로 켜는 방향 안내 |

작업 입체음향은 패드 중앙을 듣는 위치로 두고 포인터에 소리를 배치한다. 낚시는 포인터를 기준으로 숨겨진 목표의 소리를 배치한다. 목표 비콘은 농사·채광에서 남은 목표를 찾는 별도 안내이며 **Target cues**로 끌 수 있다. 상점 입장과 거래는 비입체, 이동은 누른 방향에 맞춘다. 현재 작업음은 `dry_gain: 0`으로 중앙 원음이 겹쳐 방향감이 약해지지 않게 한다. 작업 루프 도중 다시 눌러도 같은 녹음을 추가하지 않으며, 명시적 소리 이벤트가 있으면 겹치는 기존 피드백을 억제한다. 모든 소리를 입체화하는 설정은 아니다.

음성은 운영체제의 브라우저 음성 대신 고정된 영어 Piper 모델을 사용한다. 시스템은 `en_US-hfc_female-medium`, Rowan은 `en_US-hfc_male-medium`이며 내부 프로필 키는 여전히 `shopkeeper`다. 모델·WAV 캐시·보고서는 `.audio/voices/`, `.audio/cache/`, `.audio/reports/`에 저장한다. **Test guide**, **Test Rowan**, **Replay**, 음성 정지·켜기/끄기·속도·음량 조절을 제공한다. 음성 기본 음량은 85%이며 음악·효과음과 별도다.

행동 결과와 대화는 호버 문구보다 우선한다. 요청에 클라이언트·순서 정보를 넣어 늦은 응답이 최신 음성을 덮지 않게 한다. 새 NPC 대화는 이전 대화를 교체하고 일반 호버는 대화를 중단하지 않는다. 다른 창으로 이동하면 소리를 멈추고 늦은 응답을 버린다. 돌아오면 현재 음악과 호수 소리를 복구할 수 있지만 이전 대사를 다시 재생하지는 않는다. 음성 중에는 설정에 따라 음악과 일부 효과음을 낮추며 낚시 탐색음은 설정 음량을 유지한다.

시작 안내와 현재 화면의 문구는 낮은 우선순위로 미리 합성·디코딩해 첫 재생 대기를 줄인다. 준비된 음성은 재사용하며, 처음 만나는 문구나 아직 준비되지 않은 음성 모델은 합성 시간이 필요하다. 룰렛 결과도 기존 음성 우선순위·취소 처리를 따른다.

| `python engine/tools/prepare_effects_preview.py` | 효과음 모음 생성. FFmpeg·Node 필요, 실시간 HRTF 재현은 아님 |
| `python engine/tools/tactile_audit.py [--show]` | 주요 화면이 촉각 디자인 규칙(간격, 외곽선, 화면당 기호 수)을 지키는지 검사 |

실행 실패가 항상 포트 점유를 뜻하지는 않는다. 앞서 출력된 설치·음성 오류를 먼저 읽고 `check_setup.py`로 모델을 확인한다. 다운로드가 없거나 손상되었으면 설치 파일을 다시 실행한다. 접속 주소는 실행기에 표시된 값을 사용하며, 요청한 포트를 쓴다는 이유만으로 다른 프로그램을 종료하지 않는다.

## 향후 개발과 평가

추가 화초·펫·목축·요리·퀘스트·음악·제작을 확장할 계획이다. 공통 작업으로는 시각화 묶음과 원본의 차이 정리, 기능 간 직접 의존 축소가 남아 있다.

사용자 평가에서는 [촉각 디자인 참고 문헌](#촉각-디자인-참고-문헌) 끝에 정리한 질문을 함께 검증하고, 과제 성공률·수행 시간·오조작·촉각/음성 정보 이해·작업 부담을 기록한다. 구형 노트북의 포인터 지연, 카메라 보정과 가림, 도트 가독성, 발음, 입체음향은 실제 장비로 비교한다.

## 기능 추가

1. `game/<name>/`에 `feature.py`(`register(reg)`에서 `engine/core/registry.py`를 통해 화면·행동·그리기·상태·이벤트를 선언하는 `Feature` 하위 클래스)와 이를 `Feature`로 내보내는 `__init__.py`를 만든다.
2. `game/__init__.py`의 `ENABLED`에 `<name>`을 추가한다.
3. 선택: `client.js`(화면 문구), `audio/`, `assets/`, `engine/config/game.json`의 설정 항목, `game/<name>/tests/`의 테스트, README.

2단계, 설정 값, 소리, 이미지, 그리고 `engine/`의 모든 변경은 승인이 필요하다. 예시는 [game/README.md](game/README.md), 규칙은 [AGENTS.md](AGENTS.md)에 있다.

## 테스트

```
.venv\Scripts\python.exe engine\tools\run_tests.py                   # 전체
.venv\Scripts\python.exe engine\tools\run_tests.py --feature fishing # 한 기능
```

macOS/Linux에서는 `.venv/bin/python engine/tools/run_tests.py`를 쓴다. Python과 Node 테스트(Node.js 20 이상), 브라우저 점검을 실행한다(`--no-browser`로 생략 가능. 브라우저 점검에는 `pip install -r engine/requirements-dev.txt`와 `python -m playwright install chromium`이 필요). 마지막 줄이 **All green.** 이어야 한다. 알려진 실패는 테스트 안에 표시되어 있고 이유와 함께 출력된다.
